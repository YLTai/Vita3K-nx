## 实际修改

1. 在真正的 HLE bridge 记录根导出名称，导入入口保留 NID。嵌套 helper 不能用自身名称把未审计的外层调用改为已覆盖。名称赋值使用线程局部字段，不给每次导入额外增加命名锁。
2. 对六个 memcpy/memmove/memset 入口登记实际宿主目标；在 mutex/condvar/semaphore 的真实内核实现登记其实际工作区与 timeout 输出。condvar 使用 associated_mutex 的工作区，不猜调用者指针。同步无输出的线程 ID、优先级、时间、非回调 delay 和 semaphore poll 仅在核对过的入口声明空输出。
3. 未知调用仍全局排除。带回调的锁/等待在回调完成后的已审计尾部才收窄，同时推进未知历史版本，不能抹去任意回调前缀的写入。没有把 CB 函数整体当成只读，也没有覆盖异步 HLE/IPC。
4. 已登记像素与 palette 的实际宿主范围建立页反向索引。输出区间进入/退出都更新精确重叠资源的版本；同值输出仍为事件。新纹理在已有输出区间中登记时立即标为 busy。与输入不重叠的同页写入不使该输入失效。
5. 只在受监视后备受影响时重发 JIT 发布代号。无关页的映射更新单独计数，不再次打断全部纹理的发布等待。普通 Guest store 不增加新全局计数器或 bitmap 检查。

固定容量：128 个在途 HLE、1024 个输入、131072 条反向索引边。容量/版本/分配错误使资格失效；256 行 NID 归因表溢出另有计数，未知排除不因归因容量耗尽而消失。元数据锁不跨 HLE 执行、JIT、SVC、GPU 等待或异常处理器。

## 同一报告区分三层原因

保留原粗粒度 epoch 计数，同时新增 `epoch_audit.range_contracts/range_phases/range_mismatches`：

- CPU 候选 = 同步 HLE 范围候选 + 未知调用阻塞 + 输出重叠阻塞 + 历史变化/资格不足。
- HLE 范围候选 = GPU 提交代号不变候选 + GPU 提交历史排除。
- 对未知根调用按 NID/名称统计候选检查时的阻塞来源。仅归因采样为每 64 次一次；资格判断本身每次执行，不降采样、不跳 Hash。
- 最早 32 个范围候选反例独立保留，更多反例计入 dropped；分析器检查原因总数、导入进入/退出账本、反例及采样口径，不接受缺失/伪造权威字段。

**仍然每次计算参考 Hash，没有新增实际游戏 Hash 跳过。GPU 提交不等于完成，范围候选不等于 GPU 最新内容已获取。** GPU 完成、异步 HLE/IPC 和真实生命周期的复用权威尚未闭合。新版也不保护 DeviceShared 游戏页、不强制 DoubleBuffer、不收窄 shader 寻址。
