# Switch 卡顿回归热修复：撤下默认持续追踪

## 正常游玩：不再自动开启实验

日志 `1793453776` 对应 `5c0786a9` / CI #74 merge `dbad424abca98c6f5d6131467857c322107cd863`。持续模式只运行了218个渲染回调，实际跳过8次Hash、44,032个逻辑字节，随后因受监视store预算回退。回退后HLE/JIT域仍启用，整场22,807,084次HLE调用都进入元数据追踪，且保留了不再用于复用的范围查询。这是可确认的冗余成本；旧日志没有关闭追踪后的同场景对照，不能给出它占卡顿多少毫秒的因果估计。

之前约+4.39%的结果比较的是两组都带基础插桩的模式，并未量出相对于不启用追踪的总成本。它不足以支持将持续追踪设为正常游玩默认。该默认现在撤回；已得到的固定场景结果保留，不改写成普遍收益。

当前版本无需重新安装即可先停用：编辑 `sdmc:/switch/vita3k/tracelab.cfg`，将原有 `memory_validation` 项改为：

```ini
memory_validation=off
```

正常退出并重新启动游戏，使已有JIT也按未启用观察器的配置创建。不需要重跑ABBA或重新提交日志。此项不关闭独立的TraceLab采样；不要把它描述成删除所有诊断开销。

新构建中，未明确指定资源实验的配置（包括旧的 `mode=auto`、`memory_validation=on`）不再自动启用资源追踪。显式 `resource_reuse` 基准和 `resource_reuse_play` 开发模式保留，但本次不要求用户再次开启。`memory_validation=off`、`mode=off` 仍优先关闭。

## 热修复内容

1. 默认会话在创建Guest JIT前保持epoch域关闭，不分配额外观察写表，也不启用该观察器的跨页检查。原有Hash/scene memo、Direct Heap和Vulkan路径保持不变。
2. 显式持续模式终止时，先停止摘要复用并恢复所有写PTE，再关闭新的JIT/HLE/独立输出注册和读写回调观察入口。已在途的租约使用原Domain正常退出，不在运行中reset或释放它。
3. 不能简单把全局`enabled()`清零：旧JIT仍可能持有X25写表指针。保留镜像的存储与映射更新，新的JIT不再取得观察写表；映射生命周期短锁保留。旧JIT已经生成的跨页检查不会在运行中假装被移除。
4. 在调用Table::before登记资源之前检查来源排除。已知GPU/原生写入目标不再因一次最终必定回退的Hash而被登记、布防。没有放宽任何来源覆盖或复用条件。
5. 停用后HUD显示`TRACKING OFF / ORIGINAL HASH`，保留错误与计数；报告追加可选`retirement`字段，记录真实停用tick、原因及监视写入/同页非精确命中计数。旧报告没有这些证据，不补造字段。

## 自动回归和边界

实际控制器、生产Hash函数体、Table、HUD和序列化器覆盖：无配置/旧auto关闭、显式开启、显式off、启动审计、预算/策略/控制/审计失败的终止、仍在途的JIT和HLE/输出租约退出、10,000组停止后租约不新增域记录、旧镜像的映射/解除映射仍同步、被排除来源不登记、新会话重置及旧基准兼容。

恢复默认开启、保留退回后的epoch域、停止同步旧写表这三种错误版本都必须编译成功并在运行断言中被检出。既有首次审计和新页布防负例保留，未删除失败检查。

主机适配器不等于Horizon、原生A64或GPU执行；本地没有devkitA64。新目标编译、链接和打包以CI为准，不预报恢复多少帧率。本次是性能回归修复，不是新一轮硬件实验；没有新的强制日志要求。
