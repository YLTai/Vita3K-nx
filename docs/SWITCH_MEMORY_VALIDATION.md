## 本次收尾：无需按键的持续使用

新构建在没有明确选择旧实验的配置下，默认使用 `resource_reuse_play`。
启动游戏即可。每个受支持的输入先有稳定的完整 Hash 基线，再完整计算一次独立比较；通过后，在所有版本/覆盖条件仍相同时无扫描复用。
没有每 N 次检查、时间间隔跳过、像素快照复制或 GPU 提交次数代替完成的规则。
这只把既有有限来源快路径用于正常游玩，不启用 GPU 写入源，不扩展 HLE/GPU 写入权限。

Overlay：
- `PRIMING / FULL HASH`：正在建立基线及首用审计，未满足条件的输入仍完整计算。
- `ACTIVE / NORMAL PLAY`：已发生实际复用，显示跳过次数/逻辑字节、首用审计及失配。
- `FULL HASH FALLBACK`：来源不支持或追踪预算用尽，本会话停止优化但继续原路径。
- `CHECK REPORT / FULL HASH`：自动控制或审计失败，停止候选并保留反例。

**持续模式没有测试倒计时或必须等待的 DONE。正常玩，随时正常退出保存即可；无需专门重复固定场景。**
暂停/菜单不销毁已有资格，L+R+Y 不重启持续模式。退出清理恢复写页表。显式 `mode=off` / `memory_validation=off` 继续关闭该实验。

旧配置若明确写了 `validation_experiment=resource_reuse`，仍尊重其选择，保留六段基准；改为 `resource_reuse_play` 可选择持续模式。
六段基准继续原 STOCK/AUDIT/REUSE/REUSE/AUDIT/STOCK，不改变旧结果的比较口径。

## 动态输入与回退边界

新出现的纹理/别名或相关映射改变，在 renderer 回调中批量补充保护。没有待处理注册时不扫描页表；原有受监视页不会在补充过程中开放。
发布后的资格仍等待可能持有旧写表指针的 JIT 执行区间退出，随后必须重新完整计算。新生命周期必须重新首用审计。
未找到别名、未支持的输入和容量不足直接回退；不会按时间自动恢复已撤销的资格。
每个会话受监视写入预算仍有限，超过后永久回退到正常退出，不能为保持显示 ACTIVE 而重置历史。

GPU/查询回写目的地址的物理范围排除保持；shader buffer store、真实原生网络、调试写入及未知来源仍拒绝。未覆盖资源不拖住其他已覆盖资源。
首用审计不是对任意未登记写入的周期性检测。本轮设备数据只支持已测场景/受限来源；持续模式本身和更长动态游玩尚无新设备性能结论。
