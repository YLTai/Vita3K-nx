## 修复与同一次验收

禁用点移到实际条件变量等待返回、排除关闭分支之后，第一条网络工作之前。空闲、伪唤醒和关闭不禁用；一旦真正开始网络工作，位 32 仍永久保持到会话结束。断开、重新连接、重新采集不能清除它。没有假定联网安全，没有取消 GPU、调试器、地址和写入历史保护。

控制器不再让零处理量跑满六段：

- 已知全局阻塞在启动或下一次渲染回调立即结束，释放写表陷阱并恢复原路径。
- 第一个 AUDIT 结束仍为零候选审计，提前结束；不继续两个无效 REUSE 段。
- 两个 REUSE 段结束仍未省下一次 Hash，提前结束。

这些结果显示 `DONE - NO TREATMENT`，附具体原因（例如 `NATIVE NETWORK ACTIVE`、`NO AUDITABLE INPUTS`、`NO HASH SAVED`），保存部分证据但不作为性能或正确性通过。真正的审计失配优先显示 `CHECK REPORT`，不被“无处理量”提示掩盖。报告 v2 保存终止阶段和原因，分析器仍支持旧 v1，并核对各段回退计数。

## 自动回归与边界

主机测试执行实际网络等待/准入代码前缀以及真实控制器、纹理 Hash 函数体、Table、缓存、HUD、JSON：空闲/伪唤醒/关闭、实际唤醒前禁用、断开后保持、采集重启不清除；启动阻塞、零审计、零复用；别名/HLE/重映射/GPU 排除/低帧率，以及故意漏记写入必须报告失配。恢复旧线程入口禁用或删除工作前禁用，都必须在运行测试中失败。

网络 socket/协议部分用明确的哨兵代替，不声称执行了真实网络或 Horizon。主机使用系统 XXH3；CI 使用仓库锁定的头文件及目标 SDK。完整源码链和原失败门槛保留；主机通过不等于 NRO 链接或实机收益。

本次不会扩展 GPU/异步写入源的可复用范围，不增加 GPU 等待、JIT 普通 store 计数、画面周期性漏查或 live Guest RO。最终净收益和动态画面正确性仍以集成版实测为准。
