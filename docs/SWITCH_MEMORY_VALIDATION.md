# 一次采集，比较两种写追踪方案

## 只需三个动作

**替换产物根目录的 `Vita3K.nro` → 进入固定重场景按一次 L + R + Y → 看到 DONE 后正常退出。**

默认测试共 **72 秒**，自动执行 **A / B / C / C / B / A**。每段 2 秒稳定等待、10 秒采集。无需手动换模式、计时、改配置或换 NRO。启动的必要自测自动完成；已经实测过的 100 样本性能矩阵不再重复运行。

启动自测失败时，面板显示 **STARTUP CHECK FAILED**，不必再跑游戏测试，正常退出交报告即可。正常采集结束后，黄色结果、未归因变化或成本上限触发也应直接提交报告，**不要为了绿色重复同一场景**。

只需提供这一次生成的整个 `sdmc:/switch/vita3k/logs/tracelab-.../` 目录或其 ZIP。强制关闭应用、断电或崩溃不能保存尚在 RAM 中的数据；面板的完成提示不是“已写入 SD”。

## A、B、C 有什么区别

| 模式 | 普通页写入 | 选定纹理后备页写入 | 本轮要回答的问题 |
|---|---|---|---|
| A：OPEN | 直接写 | 直接写，登记 Hash 输入范围 | 共用读写表、边界检查和登记的基线 |
| B：FIRST | 直接写 | 首次回调，之后恢复直接写 | 首次写入方案的成本及开放页面后的观察缺口 |
| C：EXACT | 直接写 | 持续回调，按真实 pixel/palette 字节范围更新版本 | 精确区间证据能否解释 B 中遗漏或混淆的变化 |

所有模式都保留完整 Hash 和原来的纹理上传判断。**这次不采用固定间隔跳过 Hash，也不把尚未覆盖完整的写入版本当作缓存有效性依据。** 两种追踪策略同轮比较，避免分别发布两个 NRO、等待两轮手动结果。

在 C 中，不相关的普通 Guest 页没有全局计数或 bitmap 查询。只给已经选定的页面加回调；每段最多 100,000 次受监视写入，达到上限即开放观察页面，并记录该阶段不适合完整性能对照。未受影响的其他模式仍可独立分析。

严格的“关闭场景内 Hash memo”仅在这 72 秒采集期间生效。进入重场景之前和完成之后恢复原来的场景复用策略，避免持续承受严格参考模式的低帧率。所有阶段使用同一参考；不要把 A 当作旧版完全无插桩模拟器。

旧的 120 秒自动开始和 20/3 秒时长设置不会延长新实验；这个构建默认等待一次手动组合键。`mode=off` / `memory_validation=off` 仍受尊重。随包预设只是恢复配置的可选入口，不是第二套测试步骤。

## 同一构建自动完成的验证

启动先保留 Heap/Stack、基本 Dynarmic Run/Step/跨页/别名的正确性回归，然后对**实际游戏使用的观察器实现**执行 15 个隔离控制：首次写开放别名、开放后第二次写入的预期漏记、持续精确写、重复别名写、同值写、CPU 写后裸指针反例、同页邻接反例、显式宿主通知、CAS 成功/失败、缓存初始基线、缓存共享历史、重映射失效、palette-only 写、跨不连续宿主页、清理。

有意绕过追踪的反例只有被报告为未归因才通过。控制使用独立 scratch 内存，不注入游戏 RAM；结果不会充当自然游戏变化或污染其计数。CPU 控制在设备上经过真实 Dynarmic；主机驱动替身只能检查测试逻辑，不能冒充 ARM64 执行。

实际 TextureCache 判变点会记录：缓存前后 Hash、观察器前值、槽号、Guest 地址与范围及分类。分类之和必须等于实际判变数，并与整段 TraceLab 的 `texture_hash_changed` 对账。这样不会再把“缓存判变但观察器是首次基线”误认为“没有发生任何变化”。

`memcpy` / `memmove` / `memset` 的 libc 和 clib 六个出口提供完成后的精确宿主范围通知。它们只是已知写入证据，不是完整 HLE 或 GPU 所有权协议。

## 面板与结果

面板独立于 FPS 开关，最多 4 Hz 更新。显示段号、A/B/C、剩余时间、有效样本和自测结果。**只有实际渲染循环结束才推进完成状态**，UI 倒计时不能自行宣布完成；完成后打开退出菜单不会使结果失效。

`DONE - CAPTURE READY` 表示采集质量满足基本要求，不表示整个渲染器已通过一致性证明。没有自然变化也不必再跑：自动控制已经主动测试了检测能力。暂停或失焦会记录中断；保留这一份部分报告即可，不要盲目反复操作。

分析仅需一个脚本（标准库，无 npm/pip）：

```sh
python3 analyze-switch-capture.py session.zip --html report.html
```

它也接受会话目录。结构损坏、控制缺失、缓存对账不符会阻止性能结论；某个模式采样不足或触发回调成本上限不会丢掉另一模式的有效比较。报告保留完整分类、原始事件和排除理由。A/B/C 各两个时间对称样本，属于描述性比较，不构成统计显著性证明。

## 工程边界

新分支保留实测 v3 的全文件 Git blob 固定接线机制，只扩展缓存对账与六个 HLE 出口；CI 自动校验并展开，用户无需安装补丁或运行应用脚本。`write-watch-hooks.json` 记录实际编译源身份。禁止模糊套用接线或无视 pin 失败。

无全 JIT 安全点时，重新武装不能撤回其他 CPU 已载入的旧 PTE。宿主通知是事后通知，仍可能与 Hash 交错；GPU、其他 HLE/raw-pointer、物理内存不同 host VA 别名等尚不完全覆盖。版本未动不等于内容稳定。C 中持续回调用于区分这些问题，不预设为最终性能架构。

本构建没有新启用 Hash64、全局逐 store 慢路径、Direct Heap 或可恢复 fault，也没有声称完成新的 Vulkan 图案读回验证。新 NRO 需要完整 CI 编译/链接通过后再上机；主机测试与实机结果分开记录。
