## 修复同一证据被重复消费

回调账本记录74597次完整空检查，却有149194次消费：74597次clean、74597次conservative。真实condvar等待返回后会进入mutex重锁helper；旧实现先消费空检查证据，再检查helper声明是否匹配根调用。第二次声明被拒绝，却已污染消费统计和线程局部taint。

本版先在同一个domain短锁内验证根名称、槽状态和全部输出范围，再消费一次性证据并发布声明。错误根、无效范围、重复声明和嵌套helper拒绝不再有消费副作用。实际回调、缺失/不完整证据仍保守。**已接受的condvar声明原本保持有效，因此不把这个统计缺陷说成全部候选损失或画面错误的原因。**

## 同版本接入八个已审核运行路径

* `sceKernelSignalLwCond / All / To` 和 `sceKernelSignalSema`：在实际signal helper声明当前调用只修改宿主同步对象。等待者已有timeout/workarea输出、其他独立writer和唤醒后的Guest执行继续追踪。不能推广到会代写outBits的EventFlag或其他信号实现。
* 两个 `sceGxmReserve*DefaultUniformBuffer`：只对immediate context登记context和返回指针槽。预留操作没有写入所返回的Uniform内容；deferred回调路径保持未知。
* 两个 `sceGxmShaderPatcherCreate*Program`：仅cache-hit分支登记引用计数字段和返回指针槽。cache miss、Guest allocator回调和renderer创建路径仍未知。缓存键、程序创建、引用计数及返回值算法不变。

TLS、文件I/O、Begin/EndScene、异步写入和GPU完成没有一起放行。没有修改普通store快路径、调度、shader边界或Vulkan同步。

新增可选 `range_contracts.phase_attribution` v1：四段分别按事件发生时刻记录进入、接受声明、退出、未知结束、未知前缀及阻塞采样。保留全会话表、未归因桶和总数校验。未知结束/前缀是逐事件计数；阻塞来源仍为原1/64归因采样，**资格判断与Hash并未采样或跳过**。
