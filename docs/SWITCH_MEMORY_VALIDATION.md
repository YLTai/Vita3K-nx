## 不再仅追加函数名单：并行审核“待声明”状态能否解析

同一次ABBA保留原严格规则及其计数，另加独立的 `declaration_resolution` 观察器。它使用同一份完整参考Hash、同一CPU/映射资格和已经读取的元数据端点，不增加元数据锁、等待、复制或第二次Hash。

端点是前一次Hash开始/结束、本次Hash开始/结束。四个端点的资源版本、未知写入历史必须完全相同；任一点已有明确输出进行中都拒绝；最终端点仍有未知调用在途也拒绝。较早端点的“尚未声明”可以在最终决策前解析：不相关的已审核输出声明不会修改资源版本，而重叠声明先标忙/推进版本，未声明就返回或进入等待的调用会推进未知历史。原未知历史不会清除，未审核函数不会获得新的空输出声明。

新规则必须包含旧严格候选，否则报告失败。新增候选继续与实际完整Hash对照；前32个反例独立保存，更多反例计数不丢。报告分别统计候选、逻辑字节、排除原因、提交历史检查和反例，并与旧CPU/严格候选账本对账。

**新增候选还分成两类：本次Hash开始时未知活动已结束，以及必须等本次Hash执行期间才结束。后者不能计作Hash前可省略的工作。两类都只是事后证据，不是生产复用授权。** GPU字段比较四个端点的提交序号，仍不代表GPU完成或覆盖异步HLE/IPC。
