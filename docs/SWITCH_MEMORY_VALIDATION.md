# Switch 集成验收：实际减少普通纹理 Hash

本版在成功的 CI #69 / `a2a1cd14` 基础上接入真实普通纹理 `hash_texture_data` 快路径，不再安排候选计数或函数名单的单独实机轮次。PR #15 保持草稿；这仍是限定资源范围的实验，不是所有游戏资源的最终无损保证。

## 唯一操作

**只使用本版完整编译、链接、打包和上传成功后的产物。** 替换产物根目录 `Vita3K.nro`，启动 PCSD00035，进入同一目标重场景，按一次 **L + R + Y**。不要额外复制 core/ 下的 NRO，不需要手动改配置或切换版本。

自动执行 **STOCK → AUDIT → REUSE → REUSE → AUDIT → STOCK**。每段稳定等待 1 秒，测量至少 4 秒且取得 32 个有效渲染间隔；低帧率自动延长，单段测量预算最多 8 秒。不要按墙钟时间自行判断结束；实际回调推进 overlay 的阶段、进度、Samples、EXTENDING 和 DONE。

**任意 DONE 后正常退出，提交一个完整 TraceLab ZIP。** 黄色、零复用或失配也直接提交，不为绿色状态重复静态场景。中途失焦/暂停会中断本轮。结束后打开退出菜单不会破坏完成结果。已有有效日志不需要重跑。

## 三种模式与真实收益

- STOCK：普通完整 Hash，保留现有同场景 memo。
- AUDIT：每次执行完整参考 Hash，独立比较缓存候选，始终返回参考结果；同场景 memo 暂时关闭，避免遮住验证。
- REUSE：只对已通过实际 AUDIT 且全部版本/范围资格仍有效的输入返回缓存摘要；命中不读像素或 palette、不 memcmp、不复制、不运行 XXH3。STOCK 与 REUSE 的同场景 memo 设置相同。

性能只比较首尾 STOCK 与中间 REUSE，排除 AUDIT 的额外成本。两者仍共享写表/JIT 边界等基础插桩，不能冒充对无插桩模拟器的总收益。报告分别给出实际避免的 Hash 调用/逻辑字节、完整计算、审计、失配、回退原因与实际渲染循环耗时。工作计数包含 settling，测量耗时不包含；逻辑字节不是 DRAM 流量。

## 首版启用范围与回退

仅启用 Direct Heap + Vulkan External Host 下普通、非 GPU 写入源纹理。像素和 palette、软件别名、CPU 精确写入、同步 HLE/宿主输出、未知调用历史、JIT 旧指针发布检查及映射生命周期都参与资格判定；已复用的摘要不送进旧观察器假装又做了一次完整 Hash。

GPU surface/readback/query 输出、Guest 命令环、context 和同步对象在写入前按宿主物理范围永久排除，跨别名/地址重用仍生效，直到整个会话结束才清空。含 buffer store 的任一 shader、调试器写入、未覆盖网络后台或不支持的后端触发全局回退。不能把 GPU 提交序号或一个空账本当成完成/可见性证明。

已审核的后台通知、栈输出、状态完成、作弊修改及原生 transfer/callback 写入通过实际范围租约或保守未知区间追踪。生产者源码身份锁定；未覆盖范围仍走完整 Hash。没有增加 GPU 等待、改 shader 寻址、强制复制镜像、给游戏 Heap 设置 RO 或使用 Hash64。

新资源尚未布防、显式写入/未知操作在途、重映射、容量上限和失去覆盖时立即回退。失去覆盖会丢弃旧基线及审计资格。审计失配会记录反例、停用本会话快路径，并显示 CHECK REPORT；不把发现错误后的采集算作优化正确性通过。

## 自动验证和分析

设备启动保留现有真实观察器控制；首次普通纹理计算执行隔离的缓存动态控制（实际 renderer XXH3，像素首中尾/palette/同值事件/生命周期/覆盖撤回/故意漏记反例）。控制不修改游戏数据，不代替实际 GPU/异步压力测试。CI 执行真实控制器、真实 Hash 函数体、Table、HUD、报告，以及 clean/missing-writer/GPU-veto/remap/unsupported/slow 六类集成场景。

产物自带统一分析入口及新分析模块：

```sh
python3 analyze-switch-capture.py /path/to/tracelab-session.zip
```

零失配是本次运行证据，不是完整游戏正确性证明。特别是静态场景仍不能代表动态纹理、加载切换与所有跨线程时序；本版把自动正反例、前后审计和真实收益放在同一次启动中，必要时仅针对实际出现的缺陷追加验证。
