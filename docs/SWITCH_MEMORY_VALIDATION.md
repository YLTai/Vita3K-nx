## 同一版本的实际修复

### 所有阶段使用同一个场景 memo

旧 AUDIT 关闭场景 memo，重复检查同场景纹理；REUSE 保留 memo，真正到达资源缓存的主要是跨场景请求。Begin/EndScene 等普通帧路径尚未声明具体输出，使全局未知版本变化。主机原用例每帧调用四次，遗漏了这个真实节奏差异。

现在 STOCK、AUDIT、REUSE 都保留生产场景 memo。**AUDIT 每次实际到达普通纹理 Hash 决策时仍完整读取并返回参考值**；已有 memo 命中不伪装成新的完整审计或新的免 Hash 命中。新回归执行真实 memo 判定、控制器、Hash 函数体、Table、缓存和报告，每场景仅一次内容决策；恢复旧的未知场景入口会在运行断言中失败。

同步输出按实际位置声明：BeginScene 的 context/完整 Guest VDM 环；EndScene 额外包含实际 fragment sync 对象；18 个纹理描述符 setter 与 5 个深度/模板描述符 setter 的结构范围；VisibilityBuffer 包含 CPU 清零可能写入的完整结果范围。DisplayQueue 声明 old/new sync 对象，回调数据复制有独立的写前/写后租约；分配清零仍在原 MappingGuard 内。deferred 分配回调不放行。

Ctrl、Touch、Motion 按实际输出大小登记，Ctrl 的 count=0 原实现仍写第一项，故至少覆盖一个元素。TLS 地址查询、时钟、音频采用状态、显示设置及 notification 等经源码核对的同步叶子只声明其实际 Guest 输出；并不把后续 Guest 回调、GPU 或后台写入算成同一个只读操作。根调用不匹配仍未知。没有放行 I/O、EventFlag 的代写输出或真正的网络活动。

### 有界冲突处理，不再互相逐出审计记录

1024 项资源缓存由单槽替换改成有界开放寻址，完整比较像素、palette 和 Hash 域标识。相同槽起点的不同输入不再互相逐出；表真正满才回退，不删除其他输入的资格。失效保留键以免打断探测链，但撤销的生命周期/审计不能通过恢复几个标志复活。64 个同起点键、容量耗尽及失效链均有运行回归；恢复旧单槽实现必须失败。

新 v3 报告额外列出版本变化的具体字段；多个字段可同时改变，不当作互斥比例。旧日志没有这些字段，不能把本轮 77,963 次 VersionChanged 全部归因到某一个源。23,811 次旧 Capacity 记录也不等于表真正装满。写入来源账本和性能数据在同一份报告内，不要求额外诊断运行。
