## 同一版本的修改

### 只消费完整空检查证据

在实际 `_sceKernelWaitLwCondCB` 的 `process_callbacks` 调用周围登记线程局部证据。仅当同一根调用、线程存在且不是递归抑制、扫描正常返回并报告零回调时，允许已审核condvar尾部不再人为推进未知前缀历史。已有timeout及关联mutex输出仍全程busy。

实际回调、取消竞争后仍报告了回调、缺线程、递归抑制、未完成扫描、缺钩子、重复消费及未审核外层仍保守。非空/不完整结果在根调用内保持粘性，后面的空检查不能抹去。异常展开标记观察失败；所有元数据短锁均不跨回调、等待、Guest执行或GPU操作。

这不是CB整体只读白名单，也不表示回调启动的异步工作已完成。原 `process_callbacks` 实现和调度规则不变。

### 批量23个GXM状态入口与两个时间查询

Front/Back深度、模板、点线、polygon、fragment enable，以及Cull/RegionClip/TwoSided/VisibilityIndex/VisibilityOp：共21个可能构造命令的入口，仅在immediate context中登记context及完整Guest VDM命令环。两个precomputed state选择入口只登记context。deferred命令路径仍未知，不能借已审核helper放行外层调用。

`GetProcessTimeLow/Wide`在实际只读实现声明空Guest输出。TLS、分配、信号唤醒、Begin/EndScene、文件I/O等未审核路径不放行。不改变命令内容、shader地址边界、barrier/fence、上传、音频/Uniform算法。

### 按采集阶段记录回调检查

新增可选 `range_contracts.callback_polls` v1：全会话及四段分别记录完整空检查、非空检查、不完整检查、报告回调数、干净/保守证据消费和异常中断。按事件实际完成/消费时刻分段，包含settling；跨段的扫描和消费允许落在不同段，不伪造一一对应。

重启只清空四段计数，保留会话账本。完成后关闭phase。分析器验证分解、来源、版本、失败和无复用授权，兼容缺少该字段的旧日志而不补造证据。异常中断/溢出会进入现有CHECK REPORT路径。没有给每条普通Guest store增加计数或bitmap查询。
